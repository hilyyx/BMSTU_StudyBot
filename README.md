# BMSTU StudyBot

Обычный Telegram-бот для ИУ7-13Б: регистрация по приглашению, расписание и общая домашка в личном чате.

## Локальный запуск (PowerShell)

Требуется Python 3.11 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните `.env`:

- `BOT_TOKEN` — токен бота, созданного через [BotFather](https://t.me/BotFather).
- `OWNER_ID` — ваш числовой Telegram ID, не username. Владелец регистрируется без приглашения. После запуска команда `/id` показывает ID отправителя, даже до регистрации.
- `MAIL_CREDENTIAL_KEY` — ключ шифрования почтовых паролей. Создайте один раз командой
  `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`
  и сохраните отдельно от базы. При потере или замене ключа подключённые аккаунты придётся подключить заново.
- `MAIL_HOST`, `MAIL_PORT` — IMAP-сервер; по умолчанию `mail.bmstu.ru:993`.
- `MAIL_CHECK_INTERVAL` — интервал проверки новых писем в секундах, по умолчанию 300.

Учебные недели считаются от 31 августа 2026 (первая неделя текущего осеннего семестра). Нечётные — числитель, чётные — знаменатель. Например, 14–20 сентября — третья неделя, числитель. Бот показывает номер и тип недели автоматически; настройки недели в `.env` не нужны. Начало семестра задано в `studybot/schedule.py` (`SEMESTER_START`); для следующего семестра потребуется обновить эту дату. Расписание представляет недельный шаблон: праздники, отмены и границы семестра отдельно не учитываются.

```powershell
.\.venv\Scripts\python.exe -m studybot
```

Остановить: Ctrl+C. Одновременно запускайте только один экземпляр с этим токеном.

## Первый вход

1. Откройте личный чат с ботом и нажмите «Начать».
   Бот отправит приветственную картинку с описанием возможностей и предложит начать регистрацию. После завершённой регистрации `/start` открывает главное меню без повторного приветственного изображения.
2. Введите имя и фамилию, затем номер в журнале (1–30). Перед вводом номера бот отправит фото журнала, чтобы можно было найти свою строку.
3. Как владелец, откройте «👥 Моя группа» → «🎟 Приглашения» и выберите одно или 28 приглашений.
4. Передайте каждому студенту отдельный код. Студент нажимает «Начать», затем отправляет код и данные профиля.

После регистрации появляется главное меню с расписанием, домашкой, стендовыми и просроченными заданиями и профилем. Кнопки меняются при переходе в раздел: в профиле остаются только «✏️ Изменить профиль» и «🏠 Главное меню», а в расписании — выбор дня или недели и возврат. Вручную вводить команды для этих действий не нужно. Изменение профиля можно отменить; старые данные сохраняются до принятия нового номера. Незавершённая регистрация переживает перезапуск. Код расходуется при активации, а продолжить регистрацию можно через `/start`.

Номер в журнале задаётся самостоятельно и не может повторяться. Если номер уже занят, бот попросит проверить его; при ошибке обратитесь к владельцу. Участник получает роль студента.

Владелец видит кнопку «👥 Моя группа». Список содержит все вошедшие аккаунты, включая незавершённые регистрации: имя, номер, Telegram username, ID и роль. В блоке управления можно выбрать участника и удалить его после подтверждения. Удаляется доступ, личные отметки и черновик; опубликованные для группы задания сохраняются. Для повторного входа участнику понадобится новое приглашение. Владельца удалить нельзя. Username обновляется при обращении пользователя к боту; если его нет, показывается «не указан». У ранее зарегистрированных участников он появится после следующего сообщения боту. Участники, которые ещё не активировали приглашение, в список не попадают.

При первом запуске обновления старые повторяющиеся номера сбрасываются у всех участников конфликта; имена и доступ сохраняются. До сброса создаётся резервная копия базы в её каталоге. Затем база запрещает повторение номеров, включая одновременную регистрацию.

## Расписание

Источник — [публичный API МГТУ](https://lks.bmstu.ru/lks-back/api/v1/schedules/groups/ab0c54d0-1624-11f1-9d39-005056aae53e/public). Используется время Москвы. API проверяется при старте, затем расписание обновляется раз в час. При сбое бот показывает последнюю сохранённую копию с предупреждением; повторные попытки — не чаще раза в пять минут.

Неделя отправляется одним сообщением: краткий список пар и кнопки дней. Нажмите день для подробного расписания с аудиториями и преподавателями. Стрелки переключают дни или недели, кнопка «Вся неделя» возвращает обзор. Навигация обновляет то же сообщение.

В обзоре недели значок 📝 рядом с предметом означает, что к этой паре есть невыполненное ДЗ, а ✅ — что все задания к ней вы выполнили. При отсутствии ДЗ значка нет.

Названия предметов выделены жирным; шапка с группой и временем обновления не выводится. В расписании дня строка «ДЗ» показывается только при наличии заданий и сообщает, сколько вам осталось выполнить. Учитываются дата, тип и время пары; задания на будущие даты не смешиваются с сегодняшними. Сроки, заданные вручную, показываются у семинара или лабораторной в день дедлайна, но автоматически не привязываются к лекциям. Явно заданное ДЗ к лекции остаётся видимым. Если подходящей пары в этот день нет, задание попадёт в блок «Другие дедлайны». Кнопки под расписанием открывают карточки ДЗ на выбранный день.

SQLite находится в `data/bot.sqlite3`, хранит пользователей, хеши кодов приглашения и расписание. Каталог `data/`, `.env` и виртуальное окружение исключены из Git. Для переноса на сервер сохраните `.env` и базу.

## Домашка

1. Откройте «📚 Домашка» → «➕ Добавить ДЗ» и выберите предмет из расписания.
2. Отправьте описание, фотографии и документы (до 1800 символов и 10 вложений). Принимаются и альбомы фотографий: дождитесь их добавления перед следующим шагом. Нажмите «✅ Дальше».
3. Выберите ближайший семинар, лабораторную или лекцию. Первый вариант — семинар. Можно задать будущую дату вручную: `ДД.ММ.ГГГГ ЧЧ:ММ`; без времени срок будет 23:59. Время Москвы.
4. Укажите способ сдачи: кнопка «В тетради» либо текст с несколькими способами и ссылками на диск/Moodle (до 500 символов).
5. Проверьте карточку и подтвердите публикацию. До подтверждения задание видите только вы. Кнопка «↩️ Назад» возвращает на предыдущий шаг, «❌ Отменить» удаляет черновик. «🏠 Главное меню» сохраняет его: вернуться можно кнопкой «📝 Продолжить черновик». Черновики переживают перезапуск.

«📚 Домашка» сразу показывает ближайшие будущие дедлайны обычных и стендовых заданий, отсортированные по сроку. Стендовые работы начинаются с подписи «Стендовое ДЗ». Эмодзи типа задания остаются только на компактных кнопках и не дублируются в тексте сообщения. Текст задания отображается прямо в списке. Если задание состоит только из файлов, бот пишет «ДЗ во вложении»; если есть текст и файлы — показывает текст и пометку «Есть вложения». Полная карточка и файлы открываются кнопкой задания. Кнопка добавления обычного ДЗ находится только в нижнем меню раздела. «📋 Стендовое ДЗ» показывает невыполненные стендовые работы отдельно. Выполненные задания скрываются из этих списков только для того студента, который отметил их выполненными. При открытии задания фотографии и документы отправляются сразу, затем появляется карточка с личной отметкой «Выполнено»; повторное нажатие снимает её. При изменении отметки файлы не отправляются повторно. «🔴 Просроченное» показывает невыполненные задания обоих типов с прошедшим сроком.

Автор меняет и удаляет свои задания, владелец — любые. При изменении карточка заполняется заново, а опубликованная версия сохраняется до подтверждения. Если другой редактор успел изменить или удалить задание, старый черновик его не перезапишет. Удаление требует подтверждения и выполняется окончательно вместе с личными отметками и историей задания.

Вложения хранятся как Telegram `file_id`. Изменение расписания не переносит уже опубликованный срок. Если расписание недоступно, можно использовать сохранённую копию.

## Личный архив и невыполненное ДЗ

Кнопки «✅ Выполненное» и «📝 Невыполненное» доступны в главном меню и разделах домашки. Оба списка объединяют обычные и стендовые задания; можно выбрать предмет или открыть все задания. Невыполненное включает просроченные работы, а «🔴 Просроченное» показывает только задания с прошедшим сроком.

Архив формируется из личных отметок «Выполнено». Снятие отметки возвращает задание в основной список; у остальных студентов ничего не меняется. Отметки сохраняются после перезапуска. В расписании выполненные работы по-прежнему видны с отметкой ✅.

## Стендовое ДЗ

1. Откройте «📋 Стендовое ДЗ» → «➕ Добавить стендовое ДЗ».
2. Выберите предмет, введите название работы и прикрепите общий файл с вариантами **как документ**. Можно добавить пояснение, фотографии и другие файлы. Нажмите «✅ Дальше».
3. Введите номер учебной недели сдачи (от 1 до 52, отсчёт от начала текущего семестра). Бот покажет даты этой недели.
4. Выберите семинар или лабораторную, затем конкретную пару. ⭐ обозначает первую будущую подходящую пару на выбранной неделе. Учитываются числитель и знаменатель. Если пар нет, выберите другую неделю/тип пары или задайте дату вручную. При ручной дате номер недели пересчитывается по фактическому сроку.
5. Укажите способ сдачи, проверьте карточку и подтвердите публикацию.

Каждый студент видит исходный файл и «Твой вариант — №…» по своему номеру в журнале. Вариант не зависит от того, кто добавил работу. Выполнение личное, права изменения и восстановления те же, что у обычного ДЗ. При редактировании тип работы сохраняется.

В расписании дня стендовые работы выводятся отдельным блоком «📋 Стендовое ДЗ к сдаче», а в обзоре недели — строкой 📋 с предметом и названием работы без времени пары (✅ для выполненных). Точный срок фиксируется при публикации. Существующие обычные задания при обновлении базы сохраняются без изменений.

## Учебные материалы

В главном меню доступна кнопка «📖 Учебные материалы». Раздел содержит ссылки на папки по предметам: аналитическая геометрия, английский язык, инженерная графика, история и математический анализ, а также на весь общий Яндекс Диск.

Файлы открываются на Диске, где их можно посмотреть или скачать. Новые файлы внутри существующих папок доступны сразу; загружать их в бота не требуется. Если папку переименовали или добавили новый предмет, обновите список `SUBJECT_FOLDERS` в `studybot/materials.py`. Для просмотра раздела нужна завершённая регистрация. Кнопка возврата находится на нижней клавиатуре.

## Предложения и идеи

В профиле каждого зарегистрированного студента находится кнопка «💡 Предложения и идеи». После её нажатия следующее текстовое сообщение до 1200 символов сразу отправляется как предложение — дополнительное подтверждение или отдельная кнопка начала ввода не нужны. Предложение сохраняется в базе и сразу отправляется владельцу с именем, номером в журнале, username и Telegram ID автора. Владелец видит последние предложения через кнопку «📥 Предложения» в своём профиле. Ввод можно отменить или покинуть через главное меню. Раздел «🔴 Просроченное» также перенесён из главного меню в профиль.

## Бауманская почта

В профиле находится раздел «📨 Бауманская почта». Студент вводит полный адрес
`@student.bmstu.ru`, затем пароль. Бот проверяет учётные данные по IMAP через TLS,
запоминает последнее письмо и после этого присылает только новые письма. В уведомлении
показываются отправитель, тема, короткий текст и наличие вложений; сами вложения пока не
скачиваются.

Сообщение с паролем удаляется из чата сразу после чтения. В базе пароль хранится только
в зашифрованном виде с ключом `MAIL_CREDENTIAL_KEY`; ключ находится в серверном
`.env`. Один адрес нельзя подключить к двум профилям. При смене пароля студент выбирает
«🔄 Переподключить почту». Кнопка «🗑 Отключить почту» окончательно удаляет адрес,
зашифрованный пароль и состояние проверки. Эти данные также удаляются при удалении
участника из бота.

## Успеваемость

Кнопка «📊 Успеваемость» в профиле выполняет новый вход в личный кабинет МГТУ через
официальную страницу SSO и показывает текущий контроль, лабораторные, посещение
семинаров и опубликованные результаты сессий. Для входа используется уже подключённая
учётная запись Бауманской почты; отдельный пароль или cookie личного кабинета бот не
сохраняет. Если почта не подключена, раздел предложит сначала подключить её.

Данные загружаются по запросу пользователя и не сохраняются в базе. Формат ответа
личного кабинета может меняться без предварительного уведомления, поскольку публичная
документация этого API отсутствует.

## Структура

- `studybot/config.py` — конфигурация и проверка настроек.
- `studybot/database.py` — пользователи, приглашения, кеш расписания.
- `studybot/schedule.py` — API, чередование недель и отображение.
- `studybot/schedule_view.py` — обзор недели и кнопки навигации по расписанию.
- `studybot/handlers.py` — регистрация, профиль и разделы Telegram.
- `studybot/navigation.py` — клавиатуры разделов и переходы в главное меню.
- `studybot/materials.py` — ссылки на учебные материалы по предметам.
- `studybot/mail.py` — подключение к IMAP, шифрование и уведомления о новых письмах.
- `studybot/performance.py` — вход через SSO и отображение данных об успеваемости.
- `studybot/homework.py` — добавление, просмотр, выполнение и управление ДЗ.
- `studybot/stand_homework.py` — даты учебных недель и поиск пар сдачи стендового ДЗ.
- `studybot/__main__.py` — запуск и фоновые обновления.
- `studybot/assets/group_journal.jpg` — фото журнала для выбора номера при регистрации и изменении профиля.

Прежние команды поддерживаются для совместимости; в меню команд Telegram показывается только открытие главного меню.

Интерфейс использует [aiogram 3](https://docs.aiogram.dev/en/latest/), получение сообщений — polling.

В `handlers.py` функция `parse_number` проверяет числа, а `send_day` отправляет длинный список участников. Сами обработчики описывают шаги диалога. В `schedule.py` номер учебной недели вычисляет `academic_week`, а её тип — `week_type`.

## Сервер

На сервере Debian бот запускается службой systemd от отдельного пользователя `studybot`. Версии кода находятся в `/opt/bmstu-studybot/releases/`, текущая версия — ссылка `/opt/bmstu-studybot/current`. База хранится отдельно в `/var/lib/bmstu-studybot/bot.sqlite3`, настройки — в `/etc/bmstu-studybot.env` (доступ только root).

Команды в SSH-сеансе администратора:

```bash
systemctl status studybot
journalctl -u studybot -n 50 --no-pager
systemctl restart studybot
systemctl stop studybot
```

Служба включена при загрузке сервера и перезапускается при сбое. Не запускайте локальный экземпляр с тем же токеном одновременно с серверным.

На текущем сервере DNS-адрес Telegram `149.154.166.110` не отвечает. В `/etc/bmstu-studybot.hosts` сохранена копия системного `/etc/hosts` с записью `149.154.167.220 api.telegram.org`; этот адрес проверен по TLS-сертификату и запросом Bot API. `BindReadOnlyPaths` подключает файл только внутри службы бота. При переносе шаблона на другой сервер создайте этот файл или уберите строку `BindReadOnlyPaths`, если Telegram доступен через обычный DNS. Если закреплённый адрес перестанет отвечать, потребуется проверить доступность Telegram и обновить настройку.

Резервные копии базы создаются каждый день в 04:00 по Москве в `/var/backups/bmstu-studybot/` и хранятся 14 дней. SQLite Backup API позволяет делать копию во время работы бота. Резервные копии находятся на том же сервере; для защиты от потери сервера их нужно дополнительно сохранять вне него.

```bash
systemctl list-timers studybot-backup.timer
systemctl start studybot-backup.service
journalctl -u studybot-backup.service -n 10 --no-pager
```

Шаблоны служб и скрипт копирования находятся в `deploy/`. При обновлении создавайте новую папку версии и её виртуальное окружение, устанавливайте `requirements.txt`, затем переключайте `current` и перезапускайте службу. Не заменяйте серверную базу локальной при обновлении. Перед восстановлением базы остановите службу, сохраните текущую базу отдельно, замените её выбранной копией и верните владельца `studybot:studybot` и права `600`.

## Проверки

